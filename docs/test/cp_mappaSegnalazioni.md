# cp_mappaSegnalazioni

Specifica dei casi di test (category partition) della logica della mappa delle segnalazioni nell'interfaccia dell'Ausiliario del Traffico: funzioni pure di `src/presentation/logica/mappaSegnalazioni.ts`, usate dal boundary `:MappaSegnalazioni` (`MU_4`) con il componente mappa generico.
Requisiti: RF_OP_1 (mappa delle segnalazioni), RF_OP_6 (chiusura con esito), NRF_USA_1 (motivo e stato mai indicati solo con il colore). Task OMP-59 (issue #30); presa in carico, stato del pagamento e regola di chiusura (`azioniPer`, `rispostaAllaPresa`, `descriviPagamento`, TF-SEGUI-42…46 riscritti, 58…66 nuovi) aggiunti con OMP-63 (issue #40, RAD 0.6), con i soli casi principali (test proporzionati).

- **Fonti dell'esito atteso:** `UC_OP_1` (passi 1–4, 2.a1), `SD_OP_1` (`mostraSegnalazioniEPermessi`, `mostraDettaglio`), `UC_OP_4` (passi 1–4, 2.a1, 3.a1; `RD_10`: la segnalazione non è una sanzione), `SD_OP_4` (`indicaEsito`, `annulla`, `registraEsito`, `segnalaNonChiudibile`, `confermaChiusura`), `cp_apiSegnalazioni.md` §2 (forma delle segnalazioni, righe in qualsiasi stato con margine di 5 s, codici e messaggi di errore), `cp_risposteApi.md` (`interpretaRisposta`, `erroreDiRete`), `np_02_ausiliario.puml` (`Chiusura → Mappa`, `ErrPresa → Mappa`), `cp_apiAccesso.md` (forma di `GET /api/auth/io`: `{ utente: { id, ruolo, ente } }`), issue #30 (categorie minime: motivo; stato; modifiche ricevute; esito scelto; risposta delle API alla chiusura), piano approvato di OMP-59 (ordinamento, chiuse localmente, testi).
- **File di test:** `src/presentation/logica/mappaSegnalazioni.test.ts`, eseguito da `npm test` (ambiente node, senza database).

## 1. Tracciabilità

Ogni frame riporta un solo riferimento, scelto in quest'ordine: un requisito dell'Elenco (`RF_…`, `NRF_…`) se il suo testo copre davvero il comportamento; altrimenti il vincolo di dominio `VD_<n>`; altrimenti `ISSUE_30` per le scelte dell'issue #30 e del piano approvato.

Nome del test: `<riferimento> · <frame> · <descrizione> → <esito>`, per esempio `RF_OP_1 · TF-SEGUI-18 · riga CHIUSA di una segnalazione chiusa da un altro Ausiliario → rimossa`.

## 2. Funzioni verificate (firme)

type SegnalazioneDellaMappa = {     // come arriva da GET /api/ausiliario/segnalazioni e …/modifiche
  id: number; stalloId: number; numeroStallo: number; latitudine: number; longitudine: number;
  stato: string; motivo: string | null; targaRilevata: string | null;
  dataEOraDellaLettura: string | null; ausiliarioId: number | null; ultimaModifica: string; // ISO 8601
  tipoDiStallo?: string; // OMP-63
};
type Esito = "SOSTA_IRREGOLARE_ACCERTATA" | "NON_CONFERMATA";
type StatoChiusura =
  | { fase: "inattiva" } | { fase: "daConfermare"; esito: Esito } | { fase: "inInvio"; esito: Esito };
type EventoChiusura = { tipo: "indicaEsito"; esito: Esito } | { tipo: "annulla" } | { tipo: "conferma" };
type EsitoChiusura =
  | { tipo: "chiusa" }
  | { tipo: "nonChiudibile"; messaggio: string; rimuovi: boolean }
  | { tipo: "sessioneScaduta" }
  | { tipo: "errore"; messaggio: string };

descriviMotivo(motivo: string | null): { testo: string; tono: Tono; simbolo: string };
elementoDellaSegnalazione(segnalazione: SegnalazioneDellaMappa): ElementoMappa; // ElementoMappa di mappaStalli.ts
LEGENDA_SEGNALAZIONI: readonly { tono?: Tono; simbolo: string; testo: string }[];

CAMPI_CHIUSURA: Readonly<Record<string, string>>;  // da passare a interpretaRisposta / chiamaApi
rispostaAllaChiusura(esito: EsitoRisposta): EsitoChiusura; // EsitoRisposta di risposteApi.ts
formattaDataOra(istante: string | null): string;
// Secondo giro (revisione, punti 2 e 3)
// OMP-63: azioniPer sostituisce chiudibilitaPer di OMP-59
type Azioni = { prendiInCarico: boolean; pagamento: boolean; chiusura: boolean; messaggio: string | null };

  messaggioMappa: Messaggio | null; messaggioScheda: string | null;

- **`descriviMotivo`:** `SOSTA_ASSENTE` → «Sosta assente», `rosso`, `!`; `SOSTA_SCADUTA` → «Sosta scaduta», `arancione`, `⏱`; `TARGA_NON_CORRISPONDENTE` → «Targa non corrispondente», `viola`, `≠`; `null` → «Motivo non indicato», `grigio`, `?`; qualsiasi altro valore → «Motivo non riconosciuto», `grigio`, `?`.
- **`elementoDellaSegnalazione`:** `id`, `latitudine`, `longitudine` della segnalazione; `tono` e `simbolo` dal motivo; `simboloStato` `○` Aperta, `◐` Presa in carico, `?` altro; testo dello stato da `descriviStato("segnalazione", stato)` (`cp_statiDominio.md`); `etichetta` = `Possibile sosta irregolare, stallo n. <numeroStallo>, <testo del motivo>, targa <targa>, <testo dello stato>`, con «targa non letta» al posto di `targa <targa>` se `targaRilevata` è `null`; `gruppo` = «Segnalazioni aperte e prese in carico».
- **`LEGENDA_SEGNALAZIONI`**, nell'ordine: `{ tono: "rosso", simbolo: "!", testo: "Sosta assente" }`, `{ tono: "arancione", simbolo: "⏱", testo: "Sosta scaduta" }`, `{ tono: "viola", simbolo: "≠", testo: "Targa non corrispondente" }`, `{ tono: "grigio", simbolo: "?", testo: "Motivo non indicato o non riconosciuto" }`, `{ simbolo: "○", testo: "Aperta" }`, `{ simbolo: "◐", testo: "Presa in carico" }`.
- **`ESITI`:** `SOSTA_IRREGOLARE_ACCERTATA` → «Sosta irregolare accertata», `NON_CONFERMATA` → «Non confermata».
- **Testi (`RD_10`):** nessun testo di etichette, legenda, esiti e messaggi della logica (`azioniPer`, `azioneDopoLaChiusura`, `descriviPagamento`) contiene, senza distinzione di maiuscole, «sanzion», «multa», «infrazion», «contravvenzion», «verbale».
- **`ordinaDallaPiuRecente`:** array nuovo, dalla `dataEOraDellaLettura` più recente; quelle con lettura `null` in fondo; a parità di lettura (o tra le `null`) dall'id più alto. L'array ricevuto non viene modificato.
- **`applicaModificheSegnalazioni`:** non confronta `ultimaModifica`. Una riga non `CHIUSA` sostituisce per id la segnalazione presente o, se assente, la aggiunge; una riga `CHIUSA` rimuove la segnalazione con lo stesso id (da chiunque sia stata chiusa); una riga `CHIUSA` di un id non presente non ha effetto. Il risultato è ordinato come `ordinaDallaPiuRecente`. Se il contenuto non cambia (stesse segnalazioni con tutti i campi uguali), restituisce **lo stesso array** ricevuto; altrimenti un array nuovo. Gli array ricevuti non vengono modificati.
- **`scartaChiuseLocalmente`:** `chiuse` sono gli id chiusi da questa interfaccia. Le righe non `CHIUSA` con id in `chiuse` vengono scartate; le righe `CHIUSA` con id in `chiuse` restano e il loro id esce dall'insieme. Se nessuna riga è scartata, `righe` è lo stesso array ricevuto; se l'insieme non cambia, `chiuse` è lo stesso `Set` ricevuto, altrimenti un `Set` nuovo. Né l'array né il `Set` ricevuti vengono modificati.
- **`passoChiusura`:** da `inattiva` o `daConfermare`, `indicaEsito` → `daConfermare` con l'esito, nessuna richiesta; da `daConfermare`, `annulla` → `inattiva`, nessuna richiesta; da `daConfermare`, `conferma` → `inInvio` con lo stesso esito e richiesta `{ url: "/api/segnalazioni/<segnalazione>/chiusura", corpo: { esito } }`; `conferma` da `inattiva` o da `inInvio` → stesso stato (uguale per valore), nessuna richiesta.
- **`rispostaAllaChiusura`:** successo → `chiusa`; (OMP-63) errore sul campo `nonPresa` (`SEGNALAZIONE_NON_PRESA_IN_CARICO`) → `nonChiudibile` con il messaggio e `rimuovi: false`; errore sul campo `giaChiusa` (codice `SEGNALAZIONE_GIA_CHIUSA` tramite `CAMPI_CHIUSURA`) → `nonChiudibile` con il messaggio della API e `rimuovi: true`; campo `presaDaAltri` (`SEGNALAZIONE_PRESA_DA_ALTRI`) → `nonChiudibile` con il messaggio e `rimuovi: false`; `sessioneScaduta` → `sessioneScaduta`; ogni altro errore → `errore` con il messaggio ricevuto.
- **`formattaDataOra`:** istante ISO 8601 → `gg/mm/aaaa hh:mm` nel fuso Europe/Rome, qualunque sia quello del dispositivo; `null` → «Non disponibile».
- **`azioniPer`** (OMP-63, RAD 0.6: `UC_OP_2`, `UC_OP_3` e `UC_OP_4` entry condition, `np_02_ausiliario.puml`): `APERTA` → solo «Prendi in carico» (`{ prendiInCarico: true, pagamento: false, chiusura: false, messaggio: null }`), in ogni caso, anche con `utente` o `ausiliarioId` non noti; `PRESA_IN_CARICO` da `utente` → stato del pagamento e chiusura (`{ false, true, true, null }`); `PRESA_IN_CARICO` da un altro, con `utente` noto e `ausiliarioId` valorizzato → nessun comando e `messaggio` «Presa in carico da un altro Ausiliario.»; `PRESA_IN_CARICO` con `utente` o `ausiliarioId` non noti → stato del pagamento e chiusura: decide il server (come TF-SEGUI-45 e 46 di OMP-59). La regola «decide il server» vale solo per una `PRESA_IN_CARICO`.
- **`rispostaAllaPresa`** (OMP-63): successo con corpo `{ segnalazione }` → `presa` con la segnalazione; errore sul campo `giaChiusa` (`SEGNALAZIONE_GIA_CHIUSA` tramite `CAMPI_PRESA`) → `nonDisponibile` con il messaggio della API e `rimuovi: true`; campo `presaDaAltri` (`SEGNALAZIONE_PRESA_DA_ALTRI`) → `nonDisponibile` con `rimuovi: false`; `sessioneScaduta` → `sessioneScaduta`; ogni altro errore → `errore` con il messaggio.
- **`descriviPagamento`** (OMP-63, `UC_OP_3` passo 3): `null` → «Per la targa non risulta alcuna sosta su questo stallo.»; altrimenti «Sosta <stato>, <pagamento>: dalle <hh:mm> alle <hh:mm>.» con lo stato come in `cp_statiDominio.md` (Attiva, Scaduta, Terminata), il pagamento «pagata» o «gratuita» e gli orari di avvio e scadenza in `hh:mm` del fuso Europe/Rome.
- **`azioneDopoLaChiusura`** (`UC_OP_4` passo 4 e 2.a1, np_02 `Chiusura → Mappa` e `ErrPresa → Mappa`): `chiusa` → rimuovi, torna alla mappa, messaggio sulla mappa di successo «Segnalazione dello stallo n. <numeroStallo> chiusa: esito registrato.»; `nonChiudibile` → torna alla mappa con il messaggio della API come errore sulla mappa, e rimuovi uguale a `rimuovi` dell'esito (già chiusa sì, presa da altri no); `sessioneScaduta` → solo `accesso: true`; `errore` → resta nella scheda (nessuna rimozione, nessun ritorno) con il messaggio nella scheda, per riprovare. I campi non indicati sono `false` o `null`.
- **`utenteDaRisposta`** (`cp_apiAccesso.md`, `GET /api/auth/io`): restituisce `dati.utente.id` se `dati` è un oggetto con `utente` oggetto e `id` numero intero; in ogni altro caso `null` (utente non noto), senza eccezioni.

## 3. Ambiente

Funzioni pure: nessun database, nessuna rete, nessun DOM. Le risposte delle API si costruiscono con `interpretaRisposta(status, corpo, CAMPI_CHIUSURA)` ed `erroreDiRete()` di `risposteApi.ts`.

**Segnalazione di partenza `G(id, stato, lettura, modifiche?)`:** `{ id, stalloId: 100 + id, numeroStallo: id, latitudine: 40.688, longitudine: 14.522, stato, motivo: "SOSTA_ASSENTE", targaRilevata: "AB123CD", dataEOraDellaLettura: lettura, ausiliarioId: stato === "APERTA" ? null : 2, ultimaModifica: M1, ...modifiche }`. Ogni frame crea oggetti nuovi; «riga identica» è un oggetto distinto con gli stessi valori.

Istanti: `L1 = "2026-11-20T08:00:00.000Z"`, `L2 = "2026-11-20T08:10:00.000Z"`, `L3 = "2026-11-20T08:20:00.000Z"`, `M1 = "2026-11-20T09:00:00.000Z"`, `M2 = "2026-11-20T09:00:05.000Z"`.

Messaggi delle API (`cp_apiSegnalazioni.md`): `NONPRESA = "Prendi in carico la segnalazione prima di continuare."` (OMP-63), `GIA = "La segnalazione è già chiusa."`, `ALTRI = "La segnalazione è presa in carico da un altro Ausiliario."`, `ESITO = "Indica l'esito: sosta irregolare accertata o non confermata."`. Messaggi di `risposteApi.ts`: `RETE = "Impossibile contattare il server. Controlla la connessione e riprova."`, `GENERICO = "Si è verificato un errore. Riprova più tardi."`.

## 4. Categorie e scelte

**OMP-63 (casi principali):** comandi del dettaglio secondo stato e assegnatario (Aperta · presa da me · presa da un altro · dati non noti); risposta alla presa in carico (riuscita · presa da altri · già chiusa · sessione scaduta); stato del pagamento (Attiva pagata · Terminata gratuita · Scaduta · nessuna sosta); chiusura di una segnalazione non presa in carico.

**Motivo** (issue): sosta assente · sosta scaduta · targa non corrispondente · assente (`null`) [error] · non riconosciuto [error].

**Stato** (issue): Aperta · Presa in carico · Chiusa → rimossa (vedi modifiche ricevute) · non riconosciuto [error].

**Targa rilevata:** presente · assente [single].

**Testi:** legenda ed esiti con testo e simbolo, nessun termine di sanzione (`RD_10`).

**Ordinamento:** letture diverse · stessa lettura [single] · lettura assente [single] · nessuna segnalazione.

**Modifiche ricevute** (issue): nuova → aggiunta · già applicata [single] → nessun cambiamento · cambiata (Aperta → Presa in carico) → sostituita · chiusa da altri → rimossa · chiusa e mai vista → nessun cambiamento · nessuna riga · più righe, di tipi diversi.

**Chiuse localmente:** riga non chiusa di un id chiuso qui → scartata · riga CHIUSA di un id chiuso qui → id tolto dall'insieme · righe di altri id → invariate · insieme vuoto · risposta del polling partita prima della chiusura [single] → la segnalazione non ricompare.

**Esito scelto** (issue): accertata · non confermata · conferma annullata [single] → nessuna chiusura, nessuna richiesta · conferma senza esito indicato [error] · seconda conferma durante l'invio [error].

**Risposta delle API alla chiusura** (issue): successo · già chiusa [error] · presa da altri [error] · 401 [error] → `/accesso` · esito non valido [error] · errore di rete [error] · risposta non JSON [error].

**Data e ora della lettura:** ora solare · ora legale [single] · assente [single].

**Assegnatario prima dell'esito** (revisione, punto 2): Aperta · presa in carico dall'utente · presa in carico da un altro Ausiliario [error] → non chiudibile · utente non noto [single] → chiudibile · presa in carico senza assegnatario [single] → chiudibile.

**Dopo la risposta alla chiusura** (revisione, punto 3): chiusa · già chiusa [error] · presa da altri [error] → ritorno alla mappa, segnalazione non rimossa · sessione scaduta [error] · altro errore [error] → resta nella scheda.

**Risposta di `/api/auth/io`:** valida · `utente` mancante [error] · `utente` nullo [error] · `id` non numerico [error] · `id` non intero [error] · corpo non oggetto [error] → utente non noto.
